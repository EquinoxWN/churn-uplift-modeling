# Quality check 2026-11-01

The ten quality rules checked against the M1 code (file name kept the same as in the other repos;
the check was done on 2026-11-14 while M1 was built). Python 3.14.5 venv, Windows 11, CPU only.
The only external calls are the two dataset downloads; everything else is local file reading and
in-memory model fitting.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | `download` (`data.py`) uses `urlopen(..., timeout=60)`, HTTPS only, a 10 MB cap and a SHA-256 check; `URLError`, `TimeoutError` and `ConnectionError` are retried at most 3 times with 1 s and 2 s backoff, then raise `DataError` (`test_transient_failures_are_retried_with_backoff`, `test_retries_are_bounded_and_leave_no_partial_file`). A checksum mismatch is not retried. Unreadable files raise `DataError` with the cause; the CLI prints it and exits 2. ruff `BLE`, `S110`, `E722` clean; no `except: pass`. |
| 2 | Writes safe to retry | pass | Downloads go to a per-process `.part` file, renamed only after the checksum matches; a verified file is not fetched again (`test_a_verified_file_is_not_downloaded_again`). JSON reports are written to a temporary sibling and renamed (`files.write_text`); a failed rename keeps the old file and leaves no temporary file (`test_a_failed_write_keeps_the_old_file`). No model files are written. |
| 3 | No race conditions | pass | Single-threaded Python; scikit-learn's OpenMP threads work inside one fit call on private data. No shared mutable state; concurrent downloads use separate partial files. |
| 4 | Don't trust the clock | pass | Fit durations use `time.perf_counter` (`churn.py`, `uplift.py`). The only stored time, `created_utc` in the JSON report, is `datetime.now(UTC)` (`test_churn_prints_the_table_and_writes_utc_json` checks `+00:00`). |
| 5 | Read before changing | pass | APIs checked against the installed scikit-learn 1.9.1 (`CalibratedClassifierCV(..., cv=5, ensemble=True)`, `HistGradientBoosting*`); `mypy --strict` on NumPy, scikit-learn typed as `Any` at the boundary (no stubs exist, noted in `pyproject.toml`). The code reads no environment variables; `OMP_NUM_THREADS` is only set by `.tmp/check.sh` to limit threads (an OpenMP setting, documented in the README). Paths in docs exist (`audit_repo.py` checks README links). |
| 6 | Never break compatibility | pass | First release. Input formats are the public files as published; the Telco feature columns come from one fixed list (`TELCO_CATEGORIES`), so the encoding does not change with the rows present. JSON reports are new. |
| 7 | One source of truth | pass | Each dataset is checked against one pinned SHA-256 (with date and origin in a comment) and re-downloaded if it does not match. Allowed category values and feature names are defined once in `data.py`. Python version: `requires-python >=3.11`, README 3.11+, CI 3.12. |
| 8 | Small changes, no secrets, validate input | pass | No secrets or tokens (both sources need no sign-in). Every input is validated: CLI arguments (names, sizes, seeds, `.json` suffix), file size cap (20 MB), columns, field counts, every category value, numeric ranges and finiteness, unique customer ids, conversions without visits, both arms present, and the randomization gate. Dependencies: NumPy and scikit-learn only. |
| 9 | Tests that can fail | fixed | No skips, xfails or assertion-free tests. Mutation table below: 10 of 12 killed by the first suite; two tests added; 12 of 12 killed. Empty, invalid and failure paths are covered for each public entry point (`load_telco`, `load_hillstrom`, `download`, metrics, `fit_churn`, `evaluate_churn`, learners, `evaluate_uplift`, CLI). |

## Known limitations

- The pinned SHA-256 values are hashes of the files downloaded on 2026-11-14; no checksum is
  published upstream, so the first download was trusted (the Hillstrom mirror was compared with
  the original file).
- One holdout split per run; ECE on 1,761 Telco holdout customers moves with the seed.
- The X-learner assumes randomized assignment (constant propensity); observational data is refused
  by the randomization gate rather than handled.
